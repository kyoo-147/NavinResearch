EVIDENCE / EXPERIMENT RECEIPT

Experiments need receipts, not confetti.

A future experiment record should state inputs, method, checks, failures, and what a reviewer may conclude.

01

Freeze the question before the run.

An experiment record names the hypothesis, baseline, locked evaluation contract, seed or split policy, budget, and falsifier before execution.

EXPLORATORY OR CONFIRMATORY
  • Hypothesis
  • Baseline
  • Evaluation
02

Record the run, including failure.

Commands, environment, code and data identity, artifacts, resource use, and failed attempts belong in the receipt when a real run exists.

NO LIVE RUN PUBLISHED
  • Manifest
  • Artifacts
  • Failure class
03

Do not serve more than the receipt says.

A metric without methodology, uncertainty, and leakage checks is not a conclusion. This public page reports no result or benchmark.

INCONCLUSIVE IS ALLOWED
  • Result
  • Limitations
  • Reviewer scope
