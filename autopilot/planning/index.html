Planning sits between interpreted track context and the controller. This site describes the boundary, not an asserted production planner.

  1. 01

    Make intent visible

    A trajectory view should show what the system intends before actuation. The repository is the authority for implementation details.

    DESIGN SURFACE
    1. Track-aware route representation
    2. Planner output before control
    3. Failure cases require explicit testing
  2. 02

    Show intent before actuation.

    A planner page should let a reader distinguish a proposed route from the vehicle response. Keep target path, constraints, and fallback behaviour separate from controller performance.

    PLANNER OUTPUT / NOT EXECUTED
    1. Route representation
    2. Obstacle or sign constraints
    3. Fallback and stop condition
